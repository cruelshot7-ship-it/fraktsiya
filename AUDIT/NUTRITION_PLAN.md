### P1

**N1.1 Калькулятор.** Чистая библиотека `src/lib/nutrition-calc.ts`:
- основной обмен по Миффлину — Сан Жеору для взрослых; для групп риска — отказ с сообщением;
- коэффициенты активности и цели в `src/lib/nutrition-config.ts`, без чисел в компонентах;
- калории по макросам 4-4-9; углеводы — остаток;
- проверка, что сумма из КБЖУ совпадает с целью с учётом округления; отрицательные значения запрещены;
- история расчётов: каждая смена параметров сохраняется.
- Тесты: формулы, граничные значения, единицы, округление, некорректный ввод, группы риска.
- Зависимости: N0.1.

**N1.2 Профиль питания.** Поля: пол, возраст, рост, вес, цель, активность, шаги, силовые тренировки, приёмы пищи, предпочтения, аллергии, ограничения, бюджет.
- Обязательные, необязательные и неизвестные поля разделены; значения по умолчанию не подставляются.
- Изменения сохраняются в историю.
- Данные о здоровье — только при согласии.
- Зависимости: N1.1, решение по хранению.

**N1.3 База продуктов.** Таблица или коллекция: id, название, категория, КБЖУ на 100 г, клетчатка, источник, дата обновления, статус проверки, состояние (сырой / варёный / жареный / готовый).
- Импорт из выбранного источника или ручной ввод с указанием источника.
- Тесты: расчёт по граммовке, различие сырого и готового, отсутствующие данные.
- Зависимости: N0.1, решение по источнику.

**N1.4 Рецепты.** Ингредиенты в граммах с состоянием, шаги, время, порции, выход. КБЖУ на порцию и на 100 г вычисляются кодом.
- Миграция текста `dish-recipes.ts` в структуру — с проверкой каждого ингредиента по базе.
- Если данных не хватает — результат помечается «неполный».
- Тесты: суммирование, порция, 100 г, смена порций, замена ингредиента.
- Зависимости: N1.3.

**N1.5 Дневник.** Единые правила расчёта во всех разделах (через `sumFood` и `kcalFromMacros`). Защита от повторной отправки (ключ запроса). Границы суток по `minsk-time.ts`.
- Тесты: добавление, редактирование, удаление, дубли, граница суток.
- Зависимости: N1.1.

**N1.6 Права доступа.** Каждая функция питания проверяет принадлежность ресурса на сервере. Клиент — только свои данные и назначенные планы. Тренер — только своих клиентов.
- Интеграционные тесты: чужие данные, чужой план, тренер вне полномочий.
- Зависимости: N0.1.
