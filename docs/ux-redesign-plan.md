# UX/UI-редизайн мини-аппа «Фитнес Фракция»: аудит, структура, план

Основание: ТЗ «UX/UI-редизайн Telegram Mini App» (этапы 1–9) и концепт экранов.
Файл `AGENTS.md`, на который ссылается ТЗ, в репозитории отсутствует. Ориентиры: правила проекта из сессии и чек-лист соответствия законодательству РБ.

Принцип: один экран — одна главная задача; один главный CTA; дополнительное — по запросу.

## Этап 2. Структура интерфейса

Клиент (5 вкладок): Сегодня · Программа · Запись · Прогресс · Профиль.
- Питание — плитка на «Сегодня», не отдельная вкладка (как в концепте).
- «Профиль»: Политика конфиденциальности, Мои данные, Зал, Написать тренеру.
- Самочувствие и замеры — внутри «Прогресса», только с согласием.
- Отход от гипотезы ТЗ: вместо «Сообщения» — «Запись». Основание: утверждённый концепт (нижняя панель «Запись на тренировку»). «Написать тренеру» остаётся в «Профиле».

Тренер (5 вкладок, без изменений): Сегодня · Клиенты · Расписание · Сигналы · Программы.
- Гипотеза ТЗ (Главная · Клиенты · Расписание · Сообщения · Ещё) не принята: «Сигналы» и «Программы» — рабочие разделы, слияние — решение владельца.

## Этап 3. План по экранам

Для каждого экрана: проблема → решение → что видно → что перемещено → что скрыто → навигация → как проверить.

**Клиент · Сегодня** (A1, A2)
- Видно: приветствие с вопросом, баланс, запись, тренировка, плитка «Питание».
- Проверка: открыть «Сегодня» — имя и вопрос; тренировка даёт один главный CTA «Открыть программу».

**Клиент · навигация** (A3)
- Проверка: «Профиль» открывается на меню (не на форме); из «Прогресса» — форма; из «Записи» — записи.

**Клиент · Прогресс** (A4, A13)
- Видно (при согласии): вес и изменение за 7 дней; самочувствие и замеры (форма).
- Без согласия: только подсказка, как дать согласие («Профиль» → «Мои данные»). Компоненты не монтируются, FatSecret и «Само с часов» не вызываются.

**Клиент · Программа** (A7, A10, A12)
- Видно: день, «Я на месте» (вторичный), подходы, «Завершить подход» (главный CTA).
- Скрыто — следующий шаг: «Цикл», «Повторный максимум», «Сожжено», блоки истории над тренировкой.

**Тренер · Сегодня** (A5)
- Порядок: статистика смены → «Отметить явку» → «Заявки в зал» → «Внимание» → «Занятия».

**Тренер · карточка клиента** (A6, A8)
- Порядок: программа → последний отчёт → баланс → оплаты → питание и вес (только с согласием).

## Этап 4. Независимая проверка плана

Проверку провёл отдельный рецензент, который не видел выводов автора и сверял план с кодом. Его замечания разобраны в таблице аудита выше: подтверждённые пункты исправлены (A3, A4, A8, A10–A13), часть вынесена в следующие шаги (A7, A9), статусы в критериях приёмки снижены там, где проверка не была сделана.

Замечания, которые не исправлены в этом PR:
- **Серверная часть:** `POST /api/health` принимает данные по токену без проверки согласия. Это изменение бэкенда: по ТЗ (раздел 11) нужен отдельный план.
- **Карточка тренера:** `weightDelta` считает изменение за всю историю, а подпись говорит «за 7 дней». Исправление общим `weightChangeWeek` меняет число, которое видит тренер; в этом PR не делалось — нужно решение владельца.
- **Сигналы:** заявки в зал дублируют блок на «Сегодня»; настройки стоят в ленте сигналов. Решение владельца.
- **Программы:** вход в программу есть в «Клиенты», «Сегодня» и «Программы» — слияние не делалось.
- **Сегодня клиента:** в день визита несколько CTA («Открыть программу», «Открыть еду», «К записи»).
- **Зал:** «Как добраться» и «Сканировать» — оба выглядят главными.

## Открытые решения владельца

1. **Текст политики «Ещё → Профиль».** Поднимать `PRIVACY_VERSION` или нет. Поднятие означает, что `needsDecision` вернёт true и PrivacyGate покажут всем клиентам; до повторного согласия `specialDataAllowed` вернёт false, то есть вес и самочувствие будут скрыты у всех, пока клиенты не согласятся заново.
2. **«Сигналы»:** оставить вкладкой или свернуть в «Сегодня».
3. **«Программы» и «Клиенты»:** один вход или два.
4. **Свернуть блоки «Программы»** (A7) в этом PR или следующим.
